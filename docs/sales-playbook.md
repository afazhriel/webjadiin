# PLAYBOOK OPERASIONAL SALES & PROSPECTING — HAFI DIGITAL

> Kompas operasional harian untuk mencari, memfilter, dan menutup client Hafi Digital.
> Pelengkap `docs/client-acquisition-system.md` (strategi) — dokumen ini adalah **versi eksekusi lapangan**.
>
> **Tidak mengubah source code website.** Website production-ready tetap apa adanya. Dokumen ini murni sales & prospecting.

```
FIND → QUALIFY → AUDIT → PERSONALIZE → CONTACT → FOLLOW-UP → DISCOVERY → PROPOSAL → CLOSE → CASE STUDY
```

**PRINSIP UTAMA:** Hafi tidak mengejar semua bisnis. Hafi mencari bisnis yang:
**masalahnya terlihat** + **relevan dengan website** + **ada alasan bisnis memperbaiki** + **ada decision maker**.
Focus on relevance, not mass spam.

---

## LEGENDA KLAIM (WAJIB DIBACA)

Supaya tidak ada klaim pasar yang dibuat tanpa dasar:

- **FACT** — pernyataan umum yang dapat diverifikasi, tidak bergantung kondisi pasar tertentu.
- **INFERENCE** — kesimpulan dari pola umum cara bisnis bekerja. Masuk akal, tapi **bukan** hasil survei.
- **ASSUMPTION** — hipotesis kerja yang **wajib divalidasi** lewat observasi/discovery sebelum dijadikan dasar keputusan.

> Aturan: semua deskripsi perilaku/prioritas pasar di dokumen ini adalah **INFERENCE/ASSUMPTION** kecuali ditandai FACT. Tidak ada statistik rekaan. Validasi ke setiap prospek.

# 01 TARGET MARKET

Tidak ada "semua bisnis adalah target". Kategori dinilai dari **seberapa relevan website terhadap masalah bisnisnya**.

Format tiap kategori: `BUSINESS TYPE · WEBSITE NEED · COMMON PROBLEM · BUYING TRIGGER · DECISION MAKER · POTENTIAL OBJECTION · RELEVANCE TO HAFI`.

### 1. Jasa Profesional
- **BUSINESS TYPE:** konsultan, lawyer/notaris, akuntan, arsitek, agensi. `[FACT: kategori jasa berbasis keahlian]`
- **WEBSITE NEED:** halaman kredensial, layanan, testimoni, jalur konsultasi. `[INFERENCE]`
- **COMMON PROBLEM:** keahlian kuat tapi sulit diverifikasi online; alur kontak tidak jelas. `[INFERENCE/ASSUMPTION]`
- **BUYING TRIGGER:** naik kelas harga, mau masuk pasar korporat, mulai beriklan. `[ASSUMPTION]`
- **DECISION MAKER:** pemilik praktik / partner. `[INFERENCE]`
- **OBJECTION:** "Klien datang dari referensi." `[ASSUMPTION umum]`
- **RELEVANCE:** Tinggi — website langsung menjual trust & mempermudah inquiry. → PROFESSIONAL.

### 2. Kontraktor
- **BUSINESS TYPE:** kontraktor bangunan, interior, renovasi, mekanikal/elektrikal. `[FACT]`
- **WEBSITE NEED:** portofolio proyek + kredibilitas + form penawaran. `[INFERENCE]`
- **COMMON PROBLEM:** bukti proyek tersebar di HP/WhatsApp; calon klien sulit menilai kapasitas. `[INFERENCE/ASSUMPTION]`
- **BUYING TRIGGER:** ikut tender, ingin proyek lebih besar, mitra/developer baru. `[ASSUMPTION]`
- **DECISION MAKER:** owner/direktur. `[INFERENCE]`
- **OBJECTION:** "Proyek dari relasi." `[ASSUMPTION]`
- **RELEVANCE:** Tinggi — high-ticket, butuh bukti & kredibilitas. → PROFESSIONAL/BUSINESS.

### 3. Developer / Property
- **BUSINESS TYPE:** pengembang perumahan, agen properti, apartemen, ruko. `[FACT]`
- **WEBSITE NEED:** listing unit, galeri, lokasi, lead capture (prospek serius). `[INFERENCE]`
- **COMMON PROBLEM:** informasi unit & harga tidak terpusat; lead tidak terkelola. `[INFERENCE/ASSUMPTION]`
- **BUYING TRIGGER:** launching proyek, membuka cluster baru, kampanye iklan. `[ASSUMPTION]`
- **DECISION MAKER:** marketing manager/direktur. `[INFERENCE]`
- **OBJECTION:** "Sudah pakai marketplace properti." `[ASSUMPTION]`
- **RELEVANCE:** Tinggi — listing + leaflet digital + lead. → PROFESSIONAL/BUSINESS.

### 4. Klinik
- **BUSINESS TYPE:** klinik gigi, kecantikan, medis, fisioterapi, hewan. `[FACT]`
- **WEBSITE NEED:** layanan, dokter, jadwal, lokasi, booking/WA. `[INFERENCE]`
- **COMMON PROBLEM:** pasien baru ragu; jam & layanan tidak jelas online. `[INFERENCE/ASSUMPTION]`
- **BUYING TRIGGER:** buka cabang, tambah layanan, ingin pasien baru dari Google. `[ASSUMPTION]`
- **DECISION MAKER:** pemilik dokter/pengelola. `[INFERENCE]`
- **OBJECTION:** "Pasien dari IG/Maps." `[ASSUMPTION]`
- **RELEVANCE:** Tinggi — trust + booking lokal. → PROFESSIONAL.

### 5. Pendidikan / Training
- **BUSINESS TYPE:** sekolah, kursus, bimbel, lembaga pelatihan. `[FACT]`
- **WEBSITE NEED:** program, jadwal, pendaftaran, bukti/alumni. `[INFERENCE]`
- **COMMON PROBLEM:** pendaftaran tidak terstruktur; program sulit dibandingkan. `[INFERENCE/ASSUMPTION]`
- **BUYING TRIGGER:** periode pendaftaran, batch baru, akreditasi/ekspansi. `[ASSUMPTION]`
- **DECISION MAKER:** kepala sekolah/direktur/pemilik. `[INFERENCE]`
- **OBJECTION:** "Pendaftaran lewat WA/offline." `[ASSUMPTION]`
- **RELEVANCE:** Tinggi saat musim pendaftaran — form + info program. → PROFESSIONAL.

### 6. Distributor
- **BUSINESS TYPE:** distributor/reseller grosir, agen produk. `[FACT]`
- **WEBSITE NEED:** katalog, syarat kerja sama, area, kontak B2B. `[INFERENCE]`
- **COMMON PROBLEM:** calon mitra sulit memahami produk & skema; katalog tersebar. `[INFERENCE/ASSUMPTION]`
- **BUYING TRIGGER:** rekrut mitra, tambah lini produk, ekspansi wilayah. `[ASSUMPTION]`
- **DECISION MAKER:** owner/direktur/manajer. `[INFERENCE]`
- **OBJECTION:** "Kerja sama lewat jaringan saja." `[ASSUMPTION]`
- **RELEVANCE:** Menengah–Tinggi — katalog + lead mitra. → PROFESSIONAL/BUSINESS.

### 7. Manufaktur
- **BUSINESS TYPE:** pabrik skala kecil–menengah, produsen komponen/produk. `[FACT]`
- **WEBSITE NEED:** profil kapabilitas, katalog, spesifikasi, permintaan penawaran. `[INFERENCE]`
- **COMMON PROBLEM:** buyer korporat sulit menilai kapasitas & legalitas. `[INFERENCE/ASSUMPTION]`
- **BUYING TRIGGER:** buyer baru, tender, ekspor, sertifikasi. `[ASSUMPTION]`
- **DECISION MAKER:** owner/direktur/manajer penjualan. `[INFERENCE]`
- **OBJECTION:** "Pelanggan sudah B2B lama." `[ASSUMPTION]`
- **RELEVANCE:** Menengah–Tinggi — company profile B2B serius. → PROFESSIONAL/BUSINESS.

### 8. F&B
- **BUSINESS TYPE:** restoran, kafe, katering, produk makanan minuman. `[FACT]`
- **WEBSITE NEED:** menu, lokasi/jam, reservasi/order, brand story. `[INFERENCE]`
- **COMMON PROBLEM:** info menu & jam tersebar; order/reservasi tidak terpusat. `[INFERENCE/ASSUMPTION]`
- **BUYING TRIGGER:** buka cabang, brand baru, katering/event, promo. `[ASSUMPTION]`
- **DECISION MAKER:** owner/pengelola. `[INFERENCE]`
- **OBJECTION:** "Cukup IG & GoFood/GrabFood." `[ASSUMPTION]`
- **RELEVANCE:** Menengah — banyak yang hidup dari IG/Maps, tapi brand & katering butuh website. → STARTER/PROFESSIONAL.

### 9. Hospitality
- **BUSINESS TYPE:** hotel, villa, penginapan, tour & travel, venue. `[FACT]`
- **WEBSITE NEED:** galeri, kamar/paket, booking, lokasi. `[INFERENCE]`
- **COMMON PROBLEM:** ketergantungan OTA (komisi) & sulit direct booking. `[INFERENCE/ASSUMPTION]`
- **BUYING TRIGGER:** mau direct booking, low season promo, fasilitas baru. `[ASSUMPTION]`
- **DECISION MAKER:** owner/general manager/marketing. `[INFERENCE]`
- **OBJECTION:** "Sudah di OTA/Booking.com." `[ASSUMPTION]`
- **RELEVANCE:** Tinggi — direct booking = margin & aset sendiri. → BUSINESS.

### 10. Retail
- **BUSINESS TYPE:** toko fisik, butik, toko elektronik, grosir. `[FACT]`
- **WEBSITE NEED:** katalog/toko online, stok, checkout, ongkir. `[INFERENCE]`
- **COMMON PROBLEM:** jualan hanya offline/marketplace; margin & data pelanggan hilang. `[INFERENCE/ASSUMPTION]`
- **BUYING TRIGGER:** mau jual online sendiri, promo, brand building. `[ASSUMPTION]`
- **DECISION MAKER:** owner/pengelola. `[INFERENCE]`
- **OBJECTION:** "Marketplace sudah cukup." `[ASSUMPTION]`
- **RELEVANCE:** Tinggi untuk toko online. → BUSINESS.

### 11. UMKM yang Sedang Berkembang
- **BUSINESS TYPE:** usaha kecil yang sudah punya pelanggan rutin & mulai scale. `[FACT]`
- **WEBSITE NEED:** presence kredibel + jalur order/kontak. `[INFERENCE]`
- **COMMON PROBLEM:** brand belum "naik kelas"; hanya sosmed. `[INFERENCE/ASSUMPTION]`
- **BUYING TRIGGER:** ikut pameran, dapat mitra, iklan berbayar, naik volume. `[ASSUMPTION]`
- **DECISION MAKER:** owner. `[INFERENCE]`
- **OBJECTION:** "Belum perlu, nanti saja." `[ASSUMPTION]`
- **RELEVANCE:** Menengah–Tinggi — pintu masuk STARTER. → STARTER.

### 12. Perusahaan B2B
- **BUSINESS TYPE:** penyedia jasa/solusi untuk perusahaan lain (IT, logistik, konsultan korporat). `[FACT]`
- **WEBSITE NEED:** profil kredibel, solusi, klien, alur penawaran. `[INFERENCE]`
- **COMMON PROBLEM:** website tidak mencerminkan skala & kemampuan perusahaan. `[INFERENCE/ASSUMPTION]`
- **BUYING TRIGGER:** tender, investor, rekrutmen, ekspansi. `[ASSUMPTION]`
- **DECISION MAKER:** direktur/head of marketing/BD. `[INFERENCE]`
- **OBJECTION:** "Tim internal bisa." `[ASSUMPTION]`
- **RELEVANCE:** Tinggi — kredibilitas B2B. → PROFESSIONAL/BUSINESS.

### 13. Personal / Professional Brand
- **BUSINESS TYPE:** praktisi, mentor, coach, kreator, public figure profesional. `[FACT]`
- **WEBSITE NEED:** personal brand, penawaran, kredensial, booking/kontak. `[INFERENCE]`
- **COMMON PROBLEM:** semua bergantung platform (IG/YouTube); tidak punya "rumah" sendiri. `[INFERENCE/ASSUMPTION]`
- **BUYING TRIGGER:** luncurkan program, naikkan harga, lepas dari platform. `[ASSUMPTION]`
- **DECISION MAKER:** individu itu sendiri. `[INFERENCE]`
- **OBJECTION:** "IG saya sudah lumayan." `[ASSUMPTION]`
- **RELEVANCE:** Menengah–Tinggi — landing page personal. → STARTER/CONVERSION.

# 02 ICP (Ideal Client Profile)

## Checklist Prospect Ideal
```
[ ] Bisnis aktif
[ ] Produk/jasa jelas
[ ] Punya customer (bukti: review, konten, aktivitas)
[ ] Memiliki digital presence (IG/Maps/website)
[ ] Website belum ada ATAU perlu diperbaiki
[ ] Ada contact channel publik
[ ] Ada decision maker yang dapat diidentifikasi
[ ] Website punya masalah yang observable
[ ] Ada alasan bisnis untuk memperbaikinya
```

## Sistem Qualification Sederhana
Bukan skor 1–10 yang terlihat ilmiah. Cukup 3 keranjang:

- **PRIORITY** — ≥7 checklist terpenuhi **dan** masalah observable **dan** decision maker bisa dihubungi. → masukkan outreach sekarang.
- **NURTURE** — 4–6 checklist terpenuhi ATAU urgency belum jelas. → simpan, hubungi saat ada trigger.
- **SKIP** — <4 checklist, bisnis tidak aktif, hanya cari termurah, tidak ada decision maker. → jangan masuk pipeline.

**Gate wajib sebelum outreach:**
1. Masalah itu **benar-benar relevan dengan website?** (bukan masalah sosial media/operasional lain)
2. Ada **alasan bisnis** memperbaiki sekarang?
3. Ada **orang** yang bisa memutuskan?
Jika salah satu "tidak" → jangan outreach.

# 03 WHERE TO FIND PROSPECTS

Sembilan sumber. Untuk tiap sumber: **cara mencari · apa yang dicari · signal bagus · signal buruk**.

### 1. Google Search
- **Cara:** cari `[jenis bisnis] [kota]`, buka 2–3 halaman hasil.
- **Apa dicari:** bisnis dengan website (untuk diaudit) atau yang muncul tanpa website.
- **Signal bagus:** situs aktif tapi outdated/tidak responsif; bisnis jelas & spesifik.
- **Signal buruk:** hanya direktori/marketplace, bukan situs bisnis; bisnis fiktif/agregator.

### 2. Google Maps
- **Cara:** cari `[jenis bisnis] [kota]`, lihat listing populer.
- **Apa dicari:** bisnis aktif dengan review, tapi tanpa situs web di profil.
- **Signal bagus:** banyak review, jam jelas, tapi tanpa link website.
- **Signal buruk:** tidak ada review/aktivitas, "tutup permanen".

### 3. Instagram
- **Cara:** telusuri tag lokasi, hashtag `[jenis bisnis][kota]`, akun rekomendasi.
- **Apa dicari:** brand aktif dengan produk jelas tapi tanpa link/website (atau link mati).
- **Signal bagus:** konten rutin, ada interaksi, produk/jasa jelas, tapi bio tanpa situs.
- **Signal buruk:** akun pasif, tanpa produk jelas, hanya repost.

### 4. LinkedIn
- **Cara:** cari perusahaan `[industri] [kota/Indonesia]`; filter perusahaan kecil–menengah.
- **Apa dicari:** perusahaan B2B/personal brand profesional dengan halaman minim.
- **Signal bagus:** perusahaan nyata dengan karyawan & aktivitas, tapi tanpa website/website tipis.
- **Signal buruk:** profil kosong, tidak ada aktivitas, perusahaan tidak jelas.

### 5. Direktori Bisnis
- **Cara:** direktori UMKM/asosiasi (kamar dagang, asosiasi industri, direktori lokal).
- **Apa dicari:** bisnis terdaftar dengan kontak publik.
- **Signal bagus:** bisnis terverifikasi/tidak fiktif, kategori jelas.
- **Signal buruk:** listing duplikat/spam, data usang.

### 6. Marketplace
- **Cara:** lihat penjual terlaris di kategori tertentu.
- **Apa dicari:** seller serius yang belum punya toko/brand sendiri.
- **Signal bagus:** penjualan & ulasan tinggi, brand punya identitas.
- **Signal buruk:** reseller tanpa brand, dropshipper murni tanpa bisnis riil.

### 7. Website Perusahaan
- **Cara:** kunjungi situs industri, cek halaman mitra/klien/portfolio.
- **Apa dicari:** link ke perusahaan terkait yang website-nya bermasalah.
- **Signal bagus:** daftar klien/mitra berisi bisnis nyata (bisa jadi prospek).
- **Signal buruk:** daftar logo generik tanpa tautan.

### 8. Networking
- **Cara:** komunitas bisnis lokal, acara UMKM, chamber of commerce, coworking.
- **Apa dicari:** pemilik bisnis yang bisa mengutarakan masalah langsung.
- **Signal bagus:** menyebut masalah digital/website dalam percakapan.
- **Signal buruk:** hanya cari yang gratis/tidak serius.

### 9. Referral
- **Cara:** minta klien/relasi merekomendasikan bisnis yang butuh website.
- **Apa dicari:** prospek yang sudah hangat (ada trust dari referrer).
- **Signal bagus:** referrer mengenal decision maker & yakin ada kebutuhan.
- **Signal buruk:** referral tanpa konteks/terlalu jauh dari bisnis.

> **FACT:** informasi yang dipakai hanya yang tersedia publik. Jangan kumpulkan data pribadi sensitif.

# 05 QUALIFICATION

Alur: `FIND → saring cepat → PRIORITY/NURTURE/SKIP → isi Research Sheet`.

**Saring cepat 30 detik per prospek:**
1. Bisnis aktif? (konten/review/aktivitas)
2. Ada masalah website yang terlihat? 
3. Relevan dengan layanan Hafi?
4. Ada kontak/decision maker?

**Aturan disiplin:** jangan lanjut ke audit kalau tidak lolos gate §02. Lebih baik 5 PRIORITY daripada 50 NEW tanpa aksi.

# 06 PROSPECT RESEARCH SHEET

Struktur kolom (buat di Google Sheets/Notion; 1 baris = 1 prospek):

```
ID | Business Name | Industry | City | Website | Instagram | Contact |
Decision Maker | Website Status | Main Problem | Opportunity | Priority |
Source | Date Found | Last Contact | Next Action | Status | Notes
```

**Nilai kolom kunci:**
- **Website Status:** `Tidak ada` / `Outdated` / `Tidak responsif` / `Cukup` / `Bagus`
- **Priority:** `PRIORITY` / `NURTURE` / `SKIP`
- **Source:** `Google` / `Google Maps` / `Instagram` / `LinkedIn` / `Direktori` / `Marketplace` / `Website Perusahaan` / `Networking` / `Referral`

**Status enum (samakan dengan CRM §15):**
```
NEW → RESEARCHED → CONTACTED → REPLIED → QUALIFIED
→ CONSULTATION → PROPOSAL → WON / LOST / FOLLOW-UP
```

**Aturan keras:** setiap baris **wajib** punya **Next Action** (aksi + tanggal). Tidak ada lead tanpa next action.

# 07 WEBSITE AUDIT FRAMEWORK

Untuk setiap prospek yang punya website. Catat temuan **spesifik & dapat dibuktikan**.

### 01 FIRST IMPRESSION
- Dalam beberapa detik, apakah pengunjung paham ini bisnis apa?
- Jelas targetnya siapa?

### 02 VALUE PROPOSITION
- Mereka menjual apa?
- Untuk siapa?
- Apa manfaatnya (kenapa pilih mereka)?

### 03 TRUST
- Ada company information? portfolio? testimoni? kredensial? alamat/kontak? bukti?

### 04 UX
- Navigasi masuk akal?
- Mobile nyaman?
- Teks mudah dibaca?
- CTA jelas?
- Alur kontak mudah?

### 05 CONVERSION
- Ada CTA? WhatsApp? form kontak? alur inquiry? booking? pembelian?

### 06 PERFORMANCE
- Loading cepat/berat?
- Berat gambar?
- Layout shift?
- Performa mobile? *(ukur objektif bila memungkinkan — jangan tebak)*

### 07 SEO BASICS
- Title? meta description? struktur heading?
- Terindeks? relevansi lokal? kejelasan konten?

> **FACT:** audit hanya mencatat apa yang benar-benar terlihat. Jangan mengarang masalah yang tidak ada.

# 08 AUDIT OUTPUT

Maksimal 3 temuan. Format:

```
WHAT I FOUND
1. [Observasi spesifik]
2. [Observasi spesifik]
3. [Observasi spesifik]

WHY IT MATTERS
[Konsekuensi bisnis yang masuk akal — bukan drama]

OPPORTUNITY
[Apa yang dapat diperbaiki]

NEXT STEP
[Tawarkan audit/consultation lebih lanjut]
```

**Bahasa:** profesional.**Dilarang** "Website Anda jelek."
Contoh benar:
> "Di halaman utama, pengunjung harus scroll cukup jauh sebelum menemukan cara menghubungi bisnis."

# 11 RESPONSE HANDLING

Tujuan: **memahami kebutuhan**, bukan memaksa closing. Tanpa manipulasi.

### A. "Berapa harganya?"
> "Tergantung kebutuhan, Pak/Bu. Kami punya paket mulai dari STARTER (website landing page), PROFESSIONAL (company profile lengkap), sampai BUSINESS (toko online/custom). Supaya angkanya tepat, saya perlu tahu dulu tujuan & fitur yang dibutuhkan. Boleh saya tanya beberapa hal singkat?"

*(Lihat §12.)*

### B. "Kami belum butuh website."
> "Baik Pak/Bu, terima kasih. Kalau boleh tahu, saat ini calon pelanggan biasanya menemukan [Nama Bisnis] dari mana? Kalau memang belum jadi prioritas, saya tidak akan mengganggu — kalau nanti ada rencana, saya siap bantu."

### C. "Sudah punya website."
> "Bagus, Pak/Bu. Kalau berkenan, saya bisa cek singkat 3 poin apa yang sudah bekerja baik dan apa yang bisa dioptimalkan — tanpa biaya. Kadang ada hal kecil yang berdampak ke jumlah inquiry."

### D. "Kirim proposal saja."
> "Siap, Pak/Bu. Agar proposalnya relevan, saya perlu pahami dulu tujuan dan fitur yang dibutuhkan. Boleh saya kirim 3–4 pertanyaan singkat, atau kita jadwalkan diskusi 15 menit?"

### E. "Nanti saya pikir-pikir."
> "Tentu, Pak/Bu. Kalau ada bagian yang ingin saya perjelas — scope, timeline, atau anggaran — saya siap bantu breakdown. Kira-kira kapan waktu yang baik untuk saya follow up?"

### F. "Mahal."
> "Saya paham, Pak/Bu. Boleh saya tahu bagian mana yang di luar ekspektasi? Kami bisa sesuaikan scope dengan prioritas & anggaran — misalnya mulai dari yang paling penting dulu, lalu dikembangkan bertahap."

### G. "Boleh, jelaskan."
> "Terima kasih, Pak/Bu. Ini 3 poin singkatnya: 1) [temuan]. 2) [temuan]. 3) [temuan]. Kira-kira bagian mana yang paling ingin dibenahi lebih dulu?"

### H. Tidak membalas.
> Jangan follow-up tanpa batas. Jalankan §14 (maks. 3), lalu → **FOLLOW-UP LATER** tanpa mengirim lagi sampai ada trigger baru.

# 12 DISCOVERY QUESTIONS

Saat prospek tertarik. **Discovery first, sell second.** Dengarkan lebih banyak daripada bicara.

**BUSINESS**
- "Bisnisnya saat ini fokus di produk/jasa apa?"

**CUSTOMER**
- "Customer utama biasanya siapa?"

**CURRENT STATE**
- "Website/digital presence saat ini digunakan untuk apa?"

**PROBLEM**
- "Bagian mana yang paling ingin diperbaiki?"

**GOAL**
- "Kalau website baru selesai, hasil seperti apa yang paling penting?"

**TIMELINE**
- "Apakah ada target waktu tertentu?"

**SCOPE**
- "Fitur atau halaman apa saja yang dibutuhkan?"

Tambahan: siapa yang menyetujui keputusan; aset yang sudah ada (logo, foto, konten); apakah sudah punya domain.

---

# 13 PRICE CONVERSATION

Jangan defensif terhadap harga. Jangan menjawab hanya "Rp X".

Harga bergantung pada: **scope · jumlah halaman · design · functionality · integration · content · maintenance.**

- Jika **scope belum jelas** → arahkan ke discovery dulu.
- Jika **sudah jelas** → sebutkan paket terdekat (STARTER / PROFESSIONAL / BUSINESS) sebagai acuan, atau **"Custom quotation based on scope"**.
- **FACT:** gunakan angka resmi dari website; konfirmasi harga/promo terbaru sebelum menawarkan. Jangan mengarang harga.

**Kerangka menjawab:**
> "Untuk kebutuhan seperti yang Bapak/Ibu sebutkan, biasanya masuk ke paket [X] yang mencakup [scope]. Tapi saya ingin pastikan dulu cakupannya supaya tidak ada biaya kejutan. Boleh saya rangkum kebutuhannya?"

# 14 PROPOSAL STRUCTURE


Aturan: harga hanya muncul setelah scope jelas. Sesuaikan isi dengan temuan discovery, bukan template generik.

# 15 FOLLOW-UP SYSTEM

Maksimal **3** follow-up, lalu berhenti. Hormati opt-out.

**FOLLOW-UP 1 — check-in (2–3 hari setelah kontak/proposal)**
> "Halo Pak/Bu [Nama], saya follow up terkait pembahasan website [Business]. Kalau ada yang ingin ditanyakan, saya siap bantu."

**FOLLOW-UP 2 — value tambahan**
> "Halo Pak/Bu [Nama], sekadar berbagi: [insight/contoh relevan singkat]. Kalau perlu, saya bisa sesuaikan proposal dengan prioritas Anda."

**FOLLOW-UP 3 — close the loop**
> "Halo Pak/Bu, saya follow up terkait pembahasan website [Business]. Kalau masih dipertimbangkan, saya bisa bantu breakdown scope-nya supaya lebih mudah disesuaikan dengan kebutuhan. Kalau belum jadi prioritas sekarang, tidak masalah — saya bisa hubungi lagi saat Anda siap."

Setelah #3 tanpa respons → **FOLLOW-UP** → **FOLLOW-UP LATER**. Jangan spam.

# 16 CRM

Pipeline:
```
NEW → RESEARCHED → CONTACTED → REPLIED → QUALIFIED
→ CALL → PROPOSAL → NEGOTIATION → WON / LOST
```

Wajib per lead:
```
Business | Contact | Source | Status | Last Contact | Next Action | Potential Value | Notes
```

**Aturan:** setiap lead **wajib** punya **NEXT ACTION** (aksi + tanggal). Dilarang membiarkan lead tanpa next action.

Disiplin tambahan:
- **Overdue view:** setiap hari buka daftar dengan Next Action ≤ hari ini.
- **Stale check:** lead `CONTACTED` tanpa update >7 hari → lakukan follow-up atau tandai `FOLLOW-UP LATER`.
- **LOST harus beralasan** (harga/timing/tidak butuh/kompetitor) → bahan Learning Loop.

# 17 DAILY SALES WORKFLOW

Operasional berbasis blok, tanpa angka kaku (sesuaikan kapasitas):

**BLOCK 1 — Prospecting** → kumpulkan prospek dari §03/§04.
**BLOCK 2 — Research** → lengkapi Research Sheet (§06).
**BLOCK 3 — Audit** → audit prospek PRIORITY (§07/§08).
**BLOCK 4 — Outreach** → kirim pesan personal (§10), cek Quality Control (§18).
**BLOCK 5 — Follow-up** → kerjakan overdue + sequence (§15).
**BLOCK 6 — CRM Update** → perbarui status & next action (§16).

Prinsip: **follow-up & consultation (dekat closing) didahulukan** sebelum menambah prospek baru. Setiap sesi diakhiri CRM ter-update.

# 19 METRICS

**Track (input):**
`Prospects Found · Prospects Qualified · Messages Sent · Replies · Qualified Conversations · Consultations · Proposals · Deals Won · Deals Lost`

**Hitung (rasio):**
```
Reply Rate          = Replies ÷ Messages Sent
Qualification Rate  = Qualified ÷ Replies
Consultation Rate   = Consultations ÷ Qualified
Proposal Rate       = Proposals ÷ Consultations
Close Rate          = Deals Won ÷ Proposals
```

**Aturan:** jangan anggap angka tertentu sebagai benchmark sebelum Hafi punya data sendiri. Bandingkan **bulan ini vs bulan lalu** dan **per source per segment**.

Tambahan berguna: *Average project value · Time to close · Lead source terbaik (berdasarkan WON, bukan volume).*
